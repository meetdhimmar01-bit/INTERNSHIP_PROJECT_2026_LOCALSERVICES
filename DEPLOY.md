# Deploying LocalServices on Render

The repository includes a Render Blueprint in `render.yaml`. It installs
dependencies, collects static assets, applies migrations, starts Gunicorn, and
checks `/health/`. Render, Neon, Cloudinary, email, and Razorpay accounts must
be configured by the project owner; this repository cannot create those
accounts or provision their credentials.

## Before connecting Render

1. Revoke and replace every credential that was previously committed or
   disclosed, including database, email, and Razorpay credentials. Removing a
   value from the latest source does not remove it from Git history.
2. Create a Neon PostgreSQL database and keep its connection URL with SSL
   enabled. The URL must use the `postgresql://` scheme.
3. Create a Cloudinary account and note its cloud name, API key, and API secret.
4. Create a Render account and connect this repository. Choose **New +
   → Blueprint** and select the repository.
5. When prompted for Blueprint environment values, provide the Neon URL,
   Cloudinary credentials, an SMTP sender address and app password, and
   Razorpay credentials. Start with Razorpay test keys; switch to live keys
   only after completing payment-provider verification.
6. If you choose a custom Render service name or add a custom domain, update
   `SITE_URL` in the Render environment so account emails use the correct URL.

`DJANGO_SECRET_KEY` is generated by Render. The Blueprint disables debug mode,
restricts hosts to Render domains, enables HTTPS protections, serves collected
static files through WhiteNoise, and stores uploaded files in Cloudinary.

## Existing database and uploaded images

The first deployment applies migrations to a new database; it does not copy
records from a local PostgreSQL database. Back up and migrate required records
to Neon before directing users to the deployed site.

After uploading media, export records from the source database and import them
into Neon:

```text
python manage.py dumpdata --natural-foreign --natural-primary --exclude contenttypes --exclude auth.permission > data.json
```

Set `DATABASE_URL` to the Neon connection URL, then run:

```text
python manage.py migrate
python manage.py loaddata data.json
```

Keep `data.json` private and remove it after the import. If the old database
isn't needed, deploy with a fresh Neon database instead.

Uploaded files are not durable on a free web-service filesystem. Upload
existing images to Cloudinary and retain a backup before launch. To upload
image files currently referenced by the source database, set `DATABASE_URL` in
the local `.env` to that database, configure the Cloudinary variables, and run
`python manage.py upload_existing_media` before exporting/importing the
database. The command skips files already in Cloudinary and reports missing
local files. New uploads use Cloudinary when its credentials are configured.
Do not commit `.env` or production credentials.

## Local setup

Copy `.env.example` to `.env`, set a fresh local `DJANGO_SECRET_KEY`, and
optionally set `DATABASE_URL` to a local database. Without `DATABASE_URL`,
the project uses `db.sqlite3` for local development. Install dependencies with
`pip install -r requirements.txt`, then run:

```text
python manage.py migrate
python manage.py runserver
```

To run the production configuration locally, set `DJANGO_DEBUG=False` and
provide all required production settings. Do not use a production database or
live payment keys for local tests.
